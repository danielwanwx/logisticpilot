# 照片输入如何成为 LogisticPilot 的演示亮点

日期：2026-09-13。范围：公开一手资料调研、现有代码只读审查及下一步取舍；本轮没有修改产品代码、运行新视觉实验或写入 ERP。

## 判断

值得强化，但卖点应是 **“拍下到货，Agent 查清异常，让合格订单继续走”**。
需要让评委看到：Agent 不仅描述损伤，还能发现身份/规格/数量与订单的矛盾，主动索取最有用的下一张照片，把证据关联到批次、检验要求和履约选择。

不能宣传“大厂没有照片识货或视觉质检”。DHL 于 2026-05-07 宣布客户拍照识货进入国际寄件流程，用于生成商品描述；这是识货已有产品化的直接反例，并不等于它实现了我们的 ERPNext 收货例外闭环。[DHL 官方发布](https://group.dhl.com/en/media-relations/press-releases/2026/dhl-express-introduces-ai-powered-item-identification-for-international-shipping.html)

Cognex 已公开提供 PCB 缺件、连接器弯针、装配错位等视觉检查；MVTec MERLIC 也提供结构异常和逻辑异常检测，后者包括数量/位置不符合要求。这些是明确的现有能力，不能把“AI 看出弯针”说成技术首创；厂商效果描述也不是我们的准确率。[Cognex](https://www.cognex.cn/en/applications/assembly-inspection-and-verification/pcb-assembly-inspection-and-component-verification)、[MVTec 产品文档](https://www.mvtec.com/doc/merlic/5.8/manual/en-us/Content/Tool_reference/Processing/Deep_learning_ai/detect_anomalies_in_the_global_context.html)

Microsoft / Oracle 的原生产品、云能力和参考架构分层核查见[竞品能力笔记](2026-09-13-photo-intake-competitor-capabilities.md)。我们的差异化是假设：面向小分销商，将手机取证、少量受控商品资料和真实 ERP 动作做成一个短工作流。尚无客户对比证明我们成本更低、准确率更高或独家拥有这种组合。

## 除了破箱，还值得检查什么

以下为候选能力，不是现有模型已通过的检测清单。优先级是本项目判断。

| 优先级 | 异常 | 合适的照片与参照 | Agent 应交付的业务结果 | 不能推断什么 |
| --- | --- | --- | --- | --- |
| P0 | 错物料、错型号、错版本、错批次 | 货物全景＋清晰物料/批次标签；对照 PO、商品资料及适用批次的检验记录 | 标出字段矛盾，阻止把其他批次的放行结果套过来，请人核实归属 | 长得像不等于准确 SKU；无标签不猜型号 |
| P0 | 缺件、混装、套件组成错误 | 摊开的完整托盘或套件＋BOM/装箱规则；每件清楚分离 | 例如套件应含垫圈但可见托盘没有，生成待复核的缺件项，并查影响哪个订单 | 箱外照片不能证明箱内数量；重复视角不能重复计数 |
| P0 | 零件本体明显异常 | 正常参考照＋正面/侧面特写；任选一种真实可拍的明显弯曲、断裂、缺口或锈蚀迹象 | 指出具体可疑部位、要求另一视角，准备检验待办及相关订单影响 | 不能从色斑确定材料成分或从外观保证功能 |
| P1 | 标签与实物不一致 | 同一件货物及同一包装标签、受控规格资料 | 分开陈述“读到的标签”和“观察到的形态”，发现矛盾后暂不关联 | 不以模型常识直接改写 ERP 主数据 |
| P1 | 有效期、封口、防护包装异常 | 可读日期/包装状态＋对应物料的存储、有效期或包装要求 | 日期比对、封口状态待核实、要求开箱或补检 | 有效期必须适用于该物料；包装缺失不能证明已经发生 ESD 损伤 |
| P1 | 明显污染、异物、渗漏/受潮迹象 | 货物局部和包装近照＋表面/清洁验收规则 | 记录可见迹象，准备检验或供应商复核材料 | 不从普通 RGB 照片识别污染物化学性质或判断内部状态 |
| 延后 | 微裂纹、内伤、材料等级、硬度、导通、精密尺寸 | 检测仪器结果、检验报告；有时需要受控光学/3D 成像 | Agent 可核对报告与订单、适用批次，解释下一项检测 | 不宣称手机照片完成这些质量判定 |

这里更有价值的是 **“看起来没坏，但不是这张订单要的东西”**。这要求把观察与规格、订单关联，比再增加五种表面损伤标签更能说明 Agent 的作用。

GS1 的标签规范区分商品标识、批次、序列号和有效期；读取这些字段再做精确业务对照有标准基础。标签数量仍然是标签声明，不是独立清点。[GS1 Logistic Label Guideline](https://www.gs1.org/standards/gs1-logistic-label-guideline/1-3)

视觉质量高度依赖拍摄条件。Basler 说明不同照明适用于轮廓测量、划伤、裂纹或反光表面；因此演示选明显异常、固定背景和清楚视角，不能把普通手机图像宣传成工业测量。[Basler 照明说明](https://www.baslerweb.com/en-us/learning/illumination/)

## 当前代码最该改的地方

本轮读取 `agents/photo_receiving.py` 和 `adapters/distributor_operations.py` 后确认：

1. 当前先做全景可见性检查；只要判为 cropped/occluded，就提前返回，不进入识别、标签和表面观察。这适合限制计数，**不适合标签及缺陷特写**。近照不应因为没有拍全物体就丢掉全部价值。
2. 当前模型主要输出 visible damage / no visible damage / unclear。它没有接入特定商品的受控参考照片、BOM 或外观验收规格，不能把泛化描述称为“已按该零件标准质检”。
3. 已有图片附件、hash、ERP 批次关联、重试、可见物体坐标和批次标签矛盾字段，应复用。现有坐标是物体中心，不是缺陷定位框；不要画一个没有模型或人工证据支持的缺陷框。
4. 当前传给经济 Agent 的照片摘要包含状态、关联批次和建议，但没有完整的结构化缺陷描述、读取的 SKU 或基于商品规则的核对结果。要做错件/套件检查，必须把这些证据真正送进后续工具，不能只改前端卡片。
5. 当前 PO24 实测证明了“外箱损伤→引用照片的经济建议→20 件 ERP 出库/5 件待检”。B5 原本就受收货待检策略约束。新演示不能把这个既有 hold 冒充模型新发现的五件不良。

依据：[真实验收](../audits/2026-09-13-photo-intake-live-acceptance.md)、[旧版照片工作流设计](2026-09-08-photo-to-work-design.md)。旧设计中的广泛相册、自动找单等是历史方案，不能视为本轮已实现。

## 最小的 polish 方案

保留现有 Dashboard，不重做产品。把单图泛化识别升级成 **一个批次、按需补证据的收货检查**：

- **全景、标签、细节三种拍摄用途**：全景只负责可见数量/整体包装；标签负责身份字段；细节负责局部异常。字段分别可用或待补拍，不再一项不可用就全部失败。不是每次强制拍三张。
- **一个受控商品检查卡**：来自当前 ERP 物料、适用规格和清楚标注的正常参考照片。先做一个物料家族，避免一次覆盖螺丝、轴承、PCB 和电池。型号可能不同的物料不在历史订单上偷换，新增实验使用独立 POC 订单。
- **一个明确下一步**：例如“请拍接口正面，以确认左侧针脚是否缺失”。补拍回到同一件货物，不新增库存；保留旧照片。模型观察、规则核对和最终人工确认分开显示。
- **观察驱动下一次查询**：读取实物字段后查对应 SKU/批次规格和 QA；当身份冲突时先处理归属，数量不清则请求摊开，确有待检项时查订单及可用替代批次。不要固定每张图都跑相同四个工具后得同一个结论。
- **结果短而具体**：原图/可放大证据、发现的问题、影响的订单、仍可履约数量、一个“补拍 / 复核检验 / 查看发货方案”动作。真实 trace 放展开区。已测图像调用约21秒，应显示真实分析状态，不称毫秒级实时检测。

保持原始观察不带答案提示；在后续核对阶段提供真实预期规格是必要业务上下文。评测标签、缺陷答案、文件名提示不能混进观察阶段。读取照片内文字也不赋予文字执行指令的权限。

## 更适合录制的三段演示

同一类零件、同一张隔离演示订单，以不同证据走出不同分支：

1. **完整包装和清楚标签**：Agent 关联正确物料和批次，说明哪些检查已有证据，哪些仍未完成，不强行制造问题。
2. **表面完好但错批次/少一项套件配件**：Agent 从照片和规格的矛盾发现异常；这是主亮点。具体用哪个缺件或错批次场景，要先有一致的实物/参考图/订单并通过真实实验。
3. **细节照片模糊→具体补拍→局部异常有证据**：Agent 接续调查，生成检验复核事项，查订单影响，让已正式合格的20件继续履约；5件仍按证据处理。

一个更直观的候选是连接器：物料规格要求8针，实物正面看起来只有6针。Agent 应先要求完整正面近照，再核对是错型号、设计本就留空，还是可疑缺针；不能先把6针认定为损坏，也不能把针脚数当成收货件数。这需要有来源的正确版本规格和真实物体照片，尚未在本项目验证。若到截止前无法取得这些材料，就用一致的错批次标签场景，不临时编造工业缺陷。

这是演示设计，尚未验证这些新分支。不要把互不相关的网上照片拼成同一个真实物品的多视角；可以做明确标注的合成业务场景，但物品身份、参考规格和各视角必须自洽。

## 业务价值如何表达

优先展示“这一批到底少了什么/哪里可疑，影响哪一单，哪些货仍可发”，再量化：人工查单与重录字段数、操作员主动处理分钟数、需要人工交接的次数、有证据支持的可履约数量。把模型等待时间与人工操作时间分开。

可按同一任务人工基线与 Agent 流程比较节省的主动处理时间。返工/退货费用只有在给定且注明假设的事件概率与成本下才能估算；没有因果对照不能把订单金额视为新增收入。案例中的5件待检不是5件已被避免的次品发货。小分销商缺少总体受检分母时，只能展示“已检查批次中的异常线索”，不能称为工厂良率趋势。

## 推荐顺序

第一步做按拍摄用途分离的补拍流程和一个商品检查卡；第二步接通错批次/套件缺件中的一个分支；最后加入一个经过实测的本体异常样例。复用已有真实20件履约闭环作为终点。暂不训练专用检测器、不上连续摄像头、不扩成多品类工业质检平台。

能增强竞争力的是让评委看见 Agent 因新证据改变了下一步工作，而不是上传更多图后输出更多形容词。这个判断支持继续聚焦照片入口，但不是获奖概率或商业护城河已经成立的证明。
